## À quoi sert le plugin ?

Le plugin relie Jeedom à votre **réseau privé Tailscale**, appelé *tailnet*, et supervise vos appareils connectés.

**Accès distant sécurisé** — Accédez à Jeedom depuis l'extérieur sans redirection de port sur votre routeur, dans la plupart des configurations. Tailscale crée un réseau privé chiffré entre vos appareils.

**Accès HTTPS privé (Serve)** — Jeedom obtient une adresse HTTPS avec certificat automatique (ex : `https://jeedom.tail1234.ts.net`), accessible uniquement depuis vos appareils Tailscale. Utile pour sécuriser l'accès sans certificat à gérer, ou comme accès alternatif indépendant de votre DNS ou reverse proxy habituel.

**Accès public (Funnel)** — La même adresse rendue accessible depuis Internet, même sans Tailscale côté visiteur. Utile pour partager un accès à Jeedom avec quelqu'un qui n'a pas Tailscale, ou pour des services tiers qui doivent joindre Jeedom (webhooks, assistants vocaux). L'activation et les autorisations se configurent dans la console Tailscale.

**Accès au réseau local** — Depuis un smartphone, une tablette ou un PC connecté à Tailscale, joignez les appareils de votre réseau local (NAS, caméra, imprimante…) sans avoir à installer Tailscale sur chacun d'eux. Le mode [Subnet Router](administration.mdx#subnet-router) permet de partager tout un sous-réseau (`192.168.1.0/24`) ou un équipement précis (`192.168.1.40/32`). Le routage système et les autorisations doivent être configurés.

**Supervision des appareils** — Chaque appareil visible du tailnet devient un équipement Jeedom avec son état en ligne, son adresse et ses alertes. La latence est mesurée lors d'un ping, pas en continu. Utilisez ces informations dans vos scénarios et notifications.

Pour commencer, il suffit de connecter Jeedom et votre téléphone à Tailscale. **La configuration OAuth et les fonctions avancées sont facultatives.**

:::info Un autre chemin vers Jeedom
Tailscale offre un accès alternatif si votre adresse habituelle ou votre reverse proxy ne fonctionne plus. Jeedom doit toutefois rester allumé et disposer d'une connexion Internet, tout comme votre téléphone. Tailscale ne remplace pas une connexion Internet en panne et ne bascule pas automatiquement.
:::

## Avant de commencer {#prerequis}

- Jeedom **4.4 ou supérieur**, sur un système compatible avec le plugin, Debian 11 à 13.
- Un compte administrateur Jeedom pour installer et configurer le plugin.
- Une connexion Internet fonctionnelle sur Jeedom.
- Un compte Tailscale et [l'application Tailscale](https://tailscale.com/download) sur le téléphone ou l'ordinateur utilisé à distance.

L'installation des dépendances nécessite les droits système habituels de Jeedom. Vous n'avez pas besoin de configurer une redirection de port sur votre box pour le parcours décrit ici.

## Première connexion

### 1. Installer et activer

Dans **Plugins → Gestion des plugins**, installez Tailscale depuis le Market, puis activez-le.

Dans la configuration du plugin, attendez la fin de l'installation des **dépendances**. Si elle ne démarre pas ou si elles restent en erreur, lancez leur installation depuis cette page. Les dépendances installent le logiciel Tailscale nécessaire sur Jeedom.

### 2. Connecter Jeedom à Tailscale

Dans la configuration du plugin :

1. Cliquez sur **Se connecter à Tailscale**.
2. Ouvrez le lien d'authentification affiché.
3. Connectez-vous au compte Tailscale qui doit accueillir Jeedom et validez l'ajout.
4. Revenez dans Jeedom : le statut doit devenir **Connecté**.

Si l'état indique **En attente de validation dans la console admin**, approuvez Jeedom dans la [console Tailscale](https://login.tailscale.com/admin/machines).

### 3. Connecter votre téléphone et tester

1. Ouvrez l'application Tailscale sur votre téléphone et connectez-la au même réseau Tailscale.
2. Activez la connexion Tailscale.
3. Pour tester un véritable accès extérieur, coupez le Wi-Fi du téléphone et utilisez la 4G/5G.
4. Dans le navigateur, ouvrez l'adresse indiquée dans **Accès à Jeedom via le tailnet**, par exemple `http://100.101.102.103`.
5. Connectez-vous à Jeedom avec vos identifiants habituels.

Utilisez l'adresse réellement affichée par votre plugin. Si votre installation Jeedom utilise un port ou un chemin particulier, conservez-le dans l'adresse.

Le nom **MagicDNS**, lorsqu'il est disponible, permet de remplacer l'adresse IP par un nom plus facile à retenir. Pour obtenir une adresse HTTPS avec certificat automatique, consultez [Activer Serve](administration.mdx#serve).

### 4. Créer les équipements Jeedom

Ouvrez la page principale du plugin et cliquez sur **Synchroniser**. Le plugin crée ou met à jour un équipement par appareil visible depuis Jeedom dans Tailscale, dont Jeedom lui-même.

La synchronisation sert à la supervision : **elle n'est pas nécessaire pour ouvrir Jeedom à distance**. Elle n'installe pas Tailscale sur les autres appareils.

Un appareil disparu est signalé hors ligne ; son équipement Jeedom n'est pas automatiquement supprimé. Les choix **Activer** et **Visible** de vos équipements sont conservés.

## Utiliser les équipements

Ouvrez un équipement pour lui donner un nom, l'associer à une pièce ou choisir sa visibilité sur le tableau de bord.

**Auto-actualisation** règle la fréquence de mise à jour. Laissez ce champ vide pour un rafraîchissement toutes les minutes, ou utilisez l'assistant **?** pour choisir une autre fréquence. Exemples : `*/5 * * * *` pour toutes les 5 minutes, `0 * * * *` pour une fois par heure.

### Comprendre les informations

| Information | Signification |
| --- | --- |
| **Online** | État de connexion connu de l'appareil. Il peut y avoir un délai avant qu'un changement soit visible. |
| **IP Tailscale / IPv6** | Adresses de l'appareil dans le réseau Tailscale. |
| **Hostname** | Nom complet de l'appareil dans Tailscale. |
| **OS** | Système de l'appareil : Linux, Windows, Android, etc. |
| **Dernière activité** | Dernier contact connu ; ce n'est pas un indicateur de présence à la maison. |
| **Connexion directe / DERP** | Chemin direct entre appareils ou passage par un relais Tailscale. Un relais n'est pas une panne. |
| **Latence** | Temps de réponse du dernier test **Ping**, en millisecondes. |
| **Autorisé** | Autorisation de l'appareil dans Tailscale, renseignée grâce à OAuth. Sans cette configuration, ne l'utilisez pas comme preuve d'un refus d'accès. |
| **Expiration clé (jours)** | Délai restant lorsqu'une échéance est connue. `0` signifie expirée ; `-1` signifie aucune échéance renseignée. |

Certaines informations sont masquées par défaut. Vous pouvez choisir celles à afficher dans l'onglet **Commandes**.

Les commandes masquées restent exploitables dans les scénarios Jeedom. Par exemple, **Connexion directe** (`direct`) permet de savoir si deux appareils communiquent sans relais, **DERP** indique le nom du relais utilisé, et **Tags** liste les étiquettes Tailscale de l'appareil.

### Les actions utiles

- **Rafraîchir** met à jour les informations connues de l'appareil.
- **Ping** teste la réponse de l'appareil et actualise la latence lorsqu'il répond. La latence n'est pas mesurée automatiquement à chaque rafraîchissement.
- **Activer / Désactiver**, dans les commandes de l'équipement, autorisent ou refusent l'appareil sur Tailscale. Ces actions nécessitent OAuth et les droits administrateur.

:::note Deux sens différents pour « Activer »
La case **Activer** de la fiche équipement concerne son suivi dans Jeedom. La commande **Activer** concerne son autorisation sur Tailscale. Désautoriser un appareil sur Tailscale ne l'éteint pas et ne lui coupe pas son accès Internet habituel.
:::

### L'équipement Jeedom, repéré « Self »

**Self** désigne la machine sur laquelle ce Jeedom fonctionne. Elle dispose d'informations supplémentaires :

| Commande | Signification |
| --- | --- |
| **État** | État du service Tailscale : `Running`, `NeedsLogin`, `NeedsMachineAuth`, `Stopped`, etc. Exploitable dans un scénario pour détecter un problème de connexion. |
| **Appareils en ligne** | Nombre d'appareils actuellement connectés au tailnet. |
| **Exit node actif** | Indique si Jeedom agit comme nœud de sortie pour d'autres appareils. |
| **Subnet router actif** | Indique si Jeedom annonce des sous-réseaux. |
| **Mise à jour disponible** | Signale qu'une nouvelle version du logiciel Tailscale est disponible sur la machine. |

Ses commandes **Connecter** et **Déconnecter** pilotent la connexion de Jeedom. La commande **Mettre à jour**, masquée par défaut, concerne le logiciel Tailscale installé sur la machine ; la mise à jour du plugin reste gérée par Jeedom.

:::warning Accès distant
Si vous utilisez Tailscale pour accéder à Jeedom, **Déconnecter** interrompt cet accès. Dans la configuration, **Quitter le tailnet (logout)** exige ensuite une nouvelle authentification. Effectuez ces opérations lorsque vous disposez aussi d'un accès local.
:::

## Options et notifications

Dans **Configuration**, vous pouvez activer la **Création automatique des équipements** pour intégrer les nouveaux appareils détectés. Sinon, utilisez **Synchroniser** après leur ajout à Tailscale.

Le champ **Nom de la machine sur le tailnet** est utilisé lors de l'authentification par clé. Le modifier seul ne renomme pas immédiatement une machine déjà connectée.

Le centre de messages Jeedom peut signaler :

- une authentification à renouveler ou un appareil en attente d'approbation ;
- un nœud supprimé du tailnet (ré-authentification nécessaire) ;
- un problème de connexion au serveur de coordination Tailscale ;
- l'apparition de nouveaux appareils sur le tailnet ;
- des alertes remontées par Tailscale ;
- l'expiration prochaine de la clé d'un équipement : un rappel à **14 jours**, une alerte à **3 jours**, puis à l'expiration.

Pour éviter de vous submerger, les notifications d'état sont envoyées au maximum une fois par heure et les alertes d'expiration une fois par jour.

## Sur mobile

Le panel mobile Jeedom du plugin affiche les équipements activés que votre compte a le droit de consulter. Vous pouvez filtrer les appareils en ligne ou hors ligne, ouvrir leurs détails et lancer un rafraîchissement ou un ping selon vos droits.

L'affichage est rechargé toutes les 30 secondes. Il présente les dernières valeurs connues ; la fréquence de collecte reste celle des équipements. Les actions d'autorisation sont réservées aux administrateurs.

## Exemple : surveiller un appareil distant

Dans un scénario Jeedom, utilisez **Online** pour suivre un appareil, puis envoyez une notification s'il reste hors ligne pendant plusieurs rafraîchissements.

Pour suivre le temps de réponse, lancez périodiquement **Ping** et utilisez **Latence**. Seul l'état **Online** est historisé automatiquement à la création. Pour obtenir un graphique de latence ou du nombre d'appareils en ligne, activez manuellement l'historisation de ces commandes dans l'onglet **Commandes** de l'équipement.

Un téléphone en veille peut ne pas répondre immédiatement. Un ping sans réponse ne signifie pas systématiquement que l'appareil est éteint, et la latence affichée peut rester celle du dernier test réussi.

## Santé / Diagnostic {#diagnostic}

Le bouton **Santé / Diagnostic** ouvre une modale qui rassemble l'état du plugin en cinq sections :

| Section | Ce qu'elle vérifie |
| --- | --- |
| **Service** | Le démon `tailscaled` est actif et son socket est joignable. |
| **Réseau** | Adresses IPv4 et IPv6 Tailscale, état de MagicDNS, disponibilité UDP et UPnP. |
| **Connectivité** | Connexion directe (peer-to-peer) ou passage par un relais DERP, avec sa latence. |
| **Routage** | État du routage IP (IPv4/IPv6), du subnet router et de l'exit node. |
| **Santé** | Résumé : installation, authentification, connexion au tailnet, API OAuth et alertes Tailscale éventuelles. |

Le test OAuth/API est lancé séparément et ne bloque pas le reste du diagnostic. Si l'API est lente ou non configurée, les autres sections restent disponibles.

Une coche verte indique un état nominal. Une croix rouge signale un problème à traiter. Un tiret ou « Inconnu » signifie que l'information n'a pas pu être obtenue, ce qui n'est pas nécessairement une erreur.

**UDP** et **UPnP** aident Tailscale à établir des connexions directes entre appareils. Si l'un est absent, le trafic passe par un relais DERP : tout fonctionne, mais avec une latence plus élevée. Il n'est généralement pas nécessaire de modifier votre réseau pour cela.

Le plugin fournit aussi un résumé dans **Analyse → Santé** de Jeedom, qui inclut l'état d'accès au journal système Tailscale. Si l'accès est insuffisant, la page Santé l'indique avec des instructions. Vous pouvez corriger les permissions depuis la configuration du plugin, section **Diagnostic avancé**.

## En cas de problème

| Situation | À vérifier en premier |
| --- | --- |
| **Dépendances en erreur** | Relancez leur installation et consultez le journal `tailscale_update`. |
| **Authentification requise** | Cliquez sur **Se connecter à Tailscale** et suivez le lien. |
| **Le lien ne s'affiche pas** | Vérifiez Internet sur Jeedom, puis réessayez. La tentative de connexion dure environ trois minutes. |
| **En attente de validation** | Approuvez Jeedom dans la console Tailscale. |
| **Arrêté (down)** | Essayez **Reconnecter (up)**. Si cela échoue, consultez le diagnostic et le journal `tailscale`. |
| **Connecté mais Jeedom inaccessible** | Vérifiez Tailscale sur le téléphone, le bon réseau Tailscale, l'adresse et les règles d'accès. Testez aussi Jeedom localement. |
| **Le nom ne fonctionne pas** | Essayez l'IP Tailscale affichée. Si elle fonctionne, vérifiez MagicDNS dans la console Tailscale. |
| **API non configurée** | C'est normal si vous n'utilisez pas la gestion des appareils par OAuth. L'accès distant reste possible. |
| **Relais DERP ou UPnP absent** | Ce n'est pas nécessairement une erreur. Testez l'accès réel avant de modifier votre réseau. |
| **Routage IP désactivé** | Ce réglage concerne les fonctions de passerelle. Il n'est pas nécessaire pour accéder uniquement à Jeedom. |
| **Nœud supprimé du tailnet** | Si Jeedom a été retiré du tailnet (depuis la console Tailscale ou par expiration), le plugin vous invite à vous ré-authentifier. Cliquez sur **Se connecter à Tailscale** dans la configuration. |
| **Serveur de coordination injoignable** | Vérifiez la connexion Internet de Jeedom. Si le réseau fonctionne, le problème peut être temporaire côté Tailscale. |
| **Accès au journal insuffisant** | La page Santé vous indique si le plugin peut lire le journal Tailscale. Si l'accès est refusé, utilisez la section **Diagnostic avancé** dans la configuration du plugin pour corriger les permissions. |
| **Permission refusée** | Relancez les dépendances pour rétablir les droits prévus par le plugin, puis consultez `tailscale` si l'erreur persiste. |

Les journaux sont accessibles depuis Jeedom. Pour une demande d'aide, indiquez le statut, le message exact et la version du plugin. Ne joignez pas vos clés ni votre secret OAuth.

## Supprimer le plugin

La suppression du plugin **ne désinstalle pas le logiciel Tailscale de la machine**. Sa connexion peut donc continuer à fonctionner. Pour retirer également cet accès, prévoyez une intervention système avec un accès local et vérifiez les messages de désinstallation.

Consultez le [changelog](changelog.mdx) pour l'historique des versions.
