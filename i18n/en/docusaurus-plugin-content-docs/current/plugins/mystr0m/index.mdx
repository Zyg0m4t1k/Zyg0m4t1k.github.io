**📡 Local network required**

All myStrom and Dingz devices communicate over the **local network**. Your Jeedom box and your devices must be on the same Wi-Fi network. No cloud account is required for control.

**🔁 Automatic myStrom discovery**

Discovery uses **UDP broadcast on port 7979**. If your network is segmented (VLAN, different subnet), automatic discovery will not work — you will need to create devices manually by entering their IP address.

**⏱️ Polling and state updates**

Switch plugs and PIR use regular polling to update their state. The default interval is **10 seconds**. Buttons and Dingz work via **callback**: the device notifies Jeedom when an event occurs.

:::

## 📖 Overview

The **Smart Home** plugin integrates two ranges of Swiss-made connected devices into Jeedom:

- **myStrom** ([official site](https://mystrom.ch/fr/products/)) — smart plugs, WiFi buttons, bulbs, LED strips, motion detectors
- **Dingz** ([official site](https://www.dingz.ch/fr/produits)) — wall-mounted WiFi switches with shutters, dimmers and configurable buttons

Communication is entirely over the **local network**, with no cloud dependency. The plugin automatically handles discovery, command creation and state updates.

## 🔍 Automatic myStrom discovery

The plugin can automatically detect all myStrom devices on your local network.

1. Go to **Plugins → Plugin Management → Smart Home → Configuration**
2. Click **Scan network**
3. The plugin listens for a few seconds for myStrom device announcements
4. Detected devices are automatically created in Jeedom

The result shows the number of devices created, updated, ignored, as well as the detailed list with IP, type and MAC address.

![scan](/img/plugins/mystr0m/scan.png)

:::tip
If no device is found, create them manually from the device list (**Add** button) by entering the device type and IP address.
:::

## ⚙️ Configuring a myStrom button

:::caution Reset — only needed once
This procedure is only necessary during the **first installation** or after a **plugin update to version 2.0**.
:::

### 🔄 1. Reset the button (if already connected to the network)

1. Press and hold the button for **10 seconds**
2. It flashes red / white → release
3. Within **5 seconds**, press **once**
4. It flashes **10 times** in white

➡️ The button is reset (factory mode) — the Wi-Fi connection is cleared.

### 📱 2. Add the button in the myStrom app

1. Open the myStrom app
2. Add a device (**WiFi Button**)
3. Follow the steps until the connection is successful

### ⚡ 3. Quick synchronization with Jeedom

:::warning Must be done IMMEDIATELY after adding in the app
The button disappears quickly from the network — you have **a few seconds** to register it in Jeedom.
:::

1. Go to the plugin's **General Configuration** page
2. Click **Synchronize**, or add the device manually

### 🔧 4. Finalize in Jeedom

1. Open the created device
2. Click **Update**

✅ You should receive a confirmation (commands created successfully).

### 🎯 5. Usage

You can now associate your actions with different click types:
- **Single click**
- **Double click**
- **Long press**

Once configured, there is no need to click **Update** for each use.

:::tip Summary
1. Reset *(once only)*
2. Add in the myStrom app
3. ⚡ Quick synchronization in Jeedom
4. Update → ✅
5. Configure actions
:::

## 🔌 Switch plug

The **myStrom Switch** is a smart plug that lets you turn a device on or off remotely and measure its power consumption in real-time.

Two variants are supported:
- **Switch** — plug with CH (Swiss) connector
- **Switch EU** — plug with EU connector

### Available commands

| Command | Type | Unit | Description |
|---|---|---|---|
| State | Info | — | On (1) or off (0) |
| On | Action | — | Turns on the plug |
| Off | Action | — | Turns off the plug |
| Toggle | Action | — | Inverts the current state |
| Temperature | Info | °C | Internal plug temperature |
| Consumption | Info | W | Real-time power consumption |

### Configuration

| Field | Description |
|---|---|
| IP address | Local IP address of the plug (e.g. 192.168.1.50) |
| MAC address | Device MAC address (filled automatically during discovery) |
| Polling frequency | State update interval in seconds (default: 10 s, minimum: 2 s) |

## 🔘 WiFi Button

The **myStrom Button** is a battery-powered portable WiFi button. It detects three types of presses and triggers configurable actions in Jeedom.

### Recognized press types

| Press | Description |
|---|---|
| Single click | One short press |
| Double click | Two quick presses |
| Long press | Sustained press |

### Available commands

| Command | Type | Visible | Description |
|---|---|---|---|
| Firmware version | Info | No | Installed firmware version |
| Battery voltage | Info | Yes | Battery voltage in volts |
| Cloud reachable | Info | No | Reachability via the myStrom cloud |
| Charging | Info | No | Battery currently charging |
| Single Click | Action | No | Event triggered on each single press |
| Double Click | Action | No | Event triggered on each double press |
| Long Press | Action | No | Event triggered on each long press |
| Update | Action | Yes | Synchronizes callbacks to Jeedom |

### Configuration

![Button config](/img/plugins/mystr0m/button_config.png)

1. Enter the button's **IP address**
2. For each press type, add the **Jeedom actions** to execute (scenarios, commands from other devices…)
3. Click **Update** to send the configuration to the button — it will call Jeedom on each press

:::important How do buttons work?
When you press a myStrom button, it sends an HTTP request directly to Jeedom (callback). For this to work, **Jeedom must be reachable from the button** on the local network. Click **Update** after any configuration change so the button knows your Jeedom's address.
:::

## 🚶 Motion detector (PIR)

The **myStrom PIR** is a WiFi motion detector that also measures **temperature** and **ambient brightness**. It notifies Jeedom in real-time via callback on each detection or end of detection.

### Available commands

| Command | Type | Unit | Description |
|---|---|---|---|

### Main configuration

![PIR config](/img/plugins/mystr0m/pir_config.png)

| Field | Description |
|---|---|
| IP address | Local IP address of the PIR |
| MAC address | Filled automatically |
| Presence | Actions to execute on detection |
| Absence | Actions to execute at end of detection |

Click **Update** to register the callbacks on the device.

### Advanced PIR configuration

The **PIR Configuration** button opens an advanced settings panel sent directly to the device:

![PIR config +](/img/plugins/mystr0m/pir_config_avancee.png)

| Setting | Description |
|---|---|
| Name | Device name on the network |

| Day threshold | Brightness threshold above which it is considered day (default: 300 lux) |

## 📖 Dingz overview

The **Dingz** is a Swiss wall-mounted WiFi switch that replaces traditional switches. It includes:
- **4 capacitive buttons** independently configurable
- A front-facing color **status LED**
- A **temperature** sensor
- **Motorized shutter** management (replacing one or two shutters)
- A **PIR motion detector** (on the Dingz+ model)

The Dingz communicates entirely locally via its HTTP API. Jeedom registers callbacks on the device to be notified in real-time of each press.

## 🪟 Motorized shutters (Dingz)

When a Dingz is configured to control motorized shutters, the plugin creates associated **shutter** devices. The Dingz can manage up to **2 independent shutters**.

Each shutter is a separate device in Jeedom, linked to the parent Dingz.

### Available commands (per shutter)

| Command | Type | Unit | Description |
|---|---|---|---|
| Shutter state | Info | % | Current shutter position (0 = open, 100 = closed) |
| Slat state | Info | % | Slat angle (louvered shutters) |
| Up | Action | — | Raises the shutter |
| Down | Action | — | Lowers the shutter |
| Stop | Action | — | Stops the current movement |
| Position | Action | % (0–100) | Moves the shutter to a specific position (slider) |

:::tip
The **Position** command uses a slider from 0 to 100. **0 means the shutter is open**, **100 means the shutter is closed**.
:::

## 🏠 Using in Jeedom

Once devices are created, they are available in **Plugins → Connected Objects → Smart Home**.

Commands can be used in:
- **scenarios** — trigger an action on button press, on motion detection…
- dashboard **widgets**
- voice **interactions**
- **alerts** and notifications

Commands are automatically generated from profiles built into the plugin — no manual command configuration is needed.

### Common usage example

**myStrom Button → Jeedom Scenario:**
1. Configure the button with the IP and actions for "Single Click"
2. Add a Jeedom scenario execution in the "Single Click" block
3. Click **Update** to register on the device
4. On each press, the scenario triggers automatically

**PIR → Presence alert:**
1. Configure the PIR with the IP
2. Add a notification in the "Presence" block
3. Click **Update**
4. On each detection, Jeedom sends the notification

## 🛠️ Troubleshooting

### Automatic discovery finds no devices

- Check that your Jeedom and myStrom devices are on the same subnet
- If your network uses VLANs, UDP discovery will not cross segments — create devices manually
- Check that port 7979 is not blocked by a firewall

### A button or the Dingz no longer responds to Jeedom

- Your Jeedom's IP address may have changed — reopen the device configuration and click **Update** to re-register the callbacks
- Check that the device's IP address has not changed (assign static DHCP leases to avoid this issue)

### The Switch plug state is not updating

- Check that the plug's IP address is correct in the configuration
- Reduce the polling frequency if the state is too slow to update ("Polling frequency" field)
- Check the plugin logs (Analysis → Logs → mystr0m)

### The bulb or Dingz LED color is not applied

- Make sure the bulb / Dingz is turned on before sending a color command
- The color command uses Jeedom's native color picker

### The PIR no longer detects motion

- Click **Update** in the PIR configuration to re-register the callbacks
- Check the "Debounce delay" setting in the advanced configuration — if it is too high, the PIR considers continuous presence
- Check the plugin logs to see if PIR requests are reaching Jeedom
